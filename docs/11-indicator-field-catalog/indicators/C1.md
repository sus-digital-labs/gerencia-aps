# C1 — Mais acesso à Atenção Primária à Saúde

**Revisão:** 2026-08-26  
**Programa:** Saúde Brasil 360  
**Regra:** `C1@2026.3`  
**Status técnico:** `blocked_by_source`  
**Código de bloqueio:** `C1_BLOCKED_BY_DATA_CONTRACT`

## 1. Fonte e precedência

A fonte primária é a Nota Metodológica C1 do Ministério da Saúde [1]. O guia e-SUS APS é fonte complementar para preenchimento, campos e códigos [2]. A documentação interna nunca prevalece sobre essas publicações.

## 2. Definição normativa

O C1 mede a proporção de atendimentos de demanda programada em relação ao total de atendimentos elegíveis na APS.

```text
percentage = atendimentos_programados / atendimentos_elegiveis * 100
```

A classificação de demanda deve ser obtida do modelo de informação oficial ou de uma dimensão oficial relacionada ao fato. Não é permitido inferir o tipo de demanda por texto livre, procedimento, tipo genérico de consulta ou evidência indireta de acesso.

## 3. Bloqueio do contrato

O schema auditado de `tb_fat_atendimento_individual` não comprova a existência de uma variável confiável que distinga demanda programada e demanda espontânea. A documentação interna cita `co_dim_tipo_atendimento` e `tb_dim_tipo_atendimento` como dependências esperadas, mas isso não prova que a chave esteja presente no fato, que a dimensão esteja carregada, que os códigos estejam vigentes ou que a cardinalidade seja íntegra.

O conjunto de códigos `1`, `2`, `4`, `5` e `6` aparece em documentos internos como candidato, com `1` e `2` associados à demanda programada e `4`, `5` e `6` à espontânea. Essa codificação só pode ser utilizada depois de confirmada contra a nota metodológica, o guia vigente, a dimensão carregada e a competência.

**Decisão:** enquanto o contrato não disponibilizar e validar a classificação oficial da demanda, o C1 permanece bloqueado. A issue completa está em [c1-data-contract-issue-2026-08-26.md](../../../13-saude-brasil-360/c1-data-contract-issue-2026-08-26.md).

## 4. Contrato mínimo requerido

| Campo lógico | Requisito |
|---|---|
| Identificador do atendimento | Chave estável, não nula e deduplicável. |
| Competência/data | Compatível com a janela oficial. |
| Equipe/unidade | Chaves para filtros territoriais. |
| Profissional/CBO | Chave e code set elegível. |
| Pessoa assistida | Chave técnica, sem PII no agregado. |
| Tipo de atendimento | Chave para a dimensão oficial, presente e validável. |
| Classificação da demanda | `PROGRAMADA`, `ESPONTANEA` ou inválida, derivada do code set oficial. |
| Versão do modelo | Versão e origem do registro para rastreabilidade. |

A alternativa aceitável é incluir a chave de tipo no fato ou fornecer uma dimensão com relação um-para-um comprovada. A solução deve conservar código original, versão e linhagem; não gravar apenas o rótulo final.

O retorno bloqueado não deve conter percentual, numerador ou denominador apresentados como resultado válido. A interface deve mostrar indisponibilidade, motivo resumido e referência à issue, nunca zero.

## 6. Critérios de aceite

- [ ] Campo ou relação oficial do tipo de demanda identificado.
- [ ] Chave e dimensão disponíveis na réplica da competência.
- [ ] Cardinalidade validada sem duplicação de atendimentos.
- [ ] Code set confirmado na fonte oficial vigente.
- [ ] Registros sem classificação ficam pendentes ou são descartados com motivo explícito.
- [ ] Consulta reprodutível por competência, equipe e unidade.
- [ ] Reprocessamento idempotente.
- [ ] Versão do sistema e modelo de informação registrados.
- [ ] Ausência de dependência obrigatória produz `blocked_by_source`.
- [ ] Nenhuma PII ou SQL bruto no agregado, log ou exemplo público.

## 7. Evidência histórica de runtime

Execuções anteriores com `numerator=679`, `denominator=1713` e `percentage=39.64` são evidências técnicas datadas. Não constituem homologação normativa e não devem ser publicadas como resultado vigente enquanto o contrato permanecer incompleto.
