# Política de segurança

## Versões suportadas

A versão mais recente da branch principal recebe correções de segurança.

## Comunicação responsável

Não abra uma issue pública com detalhes exploráveis, credenciais ou dados pessoais. Use o recurso de comunicação privada de vulnerabilidades do repositório. Inclua impacto, pré-condições, arquivos afetados e uma forma segura de reproduzir o problema com dados sintéticos.

Uma confirmação inicial deve ser enviada em até cinco dias úteis. Prazos de correção dependem da gravidade e da disponibilidade de uma mitigação segura.

## Escopo

Inclui o frontend, o processo de build e os fluxos de publicação. Serviços externos e APIs implantados por terceiros devem manter políticas próprias.

## Dados sensíveis

Credenciais, endereços reais de infraestrutura, dados pessoais e dados de saúde não podem ser incluídos em issues, pull requests, logs ou fixtures.
